# 플랜두씨 다이어리 1 (T06) — 실행 가이드

## 0. 폴더 구성
- `index.html` — 앱 전체 (단일 파일, Supabase JS를 CDN에서 불러옴)
- `supabase-schema.sql` — 테이블/트리거/RLS 정책
- `seed.sql` — 초기 데이터 (브롱스커피 브랜딩 프로젝트 재개 계획 1개, 할 일 6개, 실행 기록 4건)
- `contracts/pds-schema-v2.json` — 데이터베이스 계약 문서 (표/항목/관계/날짜 규칙)

## 1. Supabase 프로젝트 (완료됨)
Seoul 리전에 프로젝트를 만들고 supabase-schema.sql, seed.sql을 SQL Editor에서 실행 완료했습니다. 실제로 계획 1개, 할 일 6개, 실행 기록 4건이 DB에 들어 있는 것을 확인했습니다.

## 2. index.html에 키 채우기 — 완료됨
index.html 상단에 프로젝트 URL과 publishable(anon) key를 이미 채워 두었습니다. publishable(anon) key는 RLS 정책으로 보호되는 공개용 키라 브라우저 코드에 그대로 들어가도 괜찮습니다. secret key는 넣지 않았습니다.

## 3. 내 실제 데이터로 채우기 (중요)
seed.sql은 "브롱스커피 브랜딩 프로젝트 재개"라는 실제 진행 중인 사이드 프로젝트를 바탕으로 한 초안입니다. 기간·마감일·예상 시간·세부 항목이 실제와 다르면 앱을 열어서 직접 고치세요 — 계획 탭의 '수정', 할 일 탭의 '수정'/'실행 기록'으로 전부 편집 가능합니다.

## 4. 배포 (GitHub Pages)
저장소 Settings → Pages에서 main 브랜치 root로 Source를 설정하면 https://superblueskt-netizen.github.io/Plan-Do-See/ 주소가 생성됩니다. 이 주소가 결과물 URL입니다.

## 5. 제출 전 최종 점검
- 새 시크릿 창에서 결과물 주소를 열어 로그인 절차 없이 바로 들어가지는지 확인 (T06-C01)
- 계획 1개 이상 + 할 일 5개 이상 + 실행 기록 3개 이상이 실제로 들어 있는지 확인 (T06-C78~80)
- 새로고침해도 값이 그대로 남는지 확인 (T06-C35)
- 완료 버튼을 빠르게 두 번 눌러도 완료 기록·집계가 1건만 늘어나는지 확인 (T06-C21/22)
- 돌아보기 화면의 숫자를 눌러 근거 기록으로 이동하는지 확인 (T06-C83)
- 검색창에 script alert 같은 문자열을 넣어 저장해보고, 그대로 글자로만 보이는지 확인 (T06-C57)
- 브라우저 개발자도구(F12)에서 index.html을 열어 anon key 외 다른 비밀값이 없는지 확인 (T06-C58)
- 내보내기 탭에서 파일 하나로 전체 자료를 내려받을 수 있는지 확인 (T06-C36)
- 첫 화면 상단 배너에 로그인 미구현 안내 문구가 보이는지 확인 (T06-C82)

## 6. 제출물 초안

### 짧은 확인 방법 (4줄)
어디로 가나요: 결과물 URL을 새 시크릿 창으로 엽니다.
무엇을 하나요(3단계 이내): 1) 계획 탭에서 계획을 확인 2) 할 일 탭에서 할 일 하나를 완료 처리 3) 돌아보기 탭에서 완료 수 숫자를 클릭합니다.
무엇이 보이면 통과인가요: 완료 수가 1 늘어나고, 그 숫자를 클릭하면 방금 완료한 할 일이 목록에 보입니다.
안 될 때는 무엇이 보이나요: 저장/수정 버튼을 눌렀을 때 alert 창으로 실패 이유(Supabase 오류 메시지)가 뜹니다.

### AI와 내 판단 (3줄)
AI에게 맡긴 일: 데이터베이스 스키마 설계(계획 수정 이력 트리거, 완료 중복 방지 로직 포함), 단일 파일 프런트엔드 전체 구현, Supabase SQL Editor에서 스키마·초기 데이터 실행까지 진행.
내가 직접 판단한 일: 카드1 실제 계획으로 "브롱스커피 브랜딩 프로젝트 재개"를 선택했고, Supabase를 새 프로젝트로 분리하기로 정했고, GitHub 업로드는 웹 에디터로 직접 진행.
AI 말을 안 들은 일: (없으면) 이번에는 AI가 제시한 스키마·구현 방식을 그대로 채택했다.
